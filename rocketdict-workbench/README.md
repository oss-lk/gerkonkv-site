# RocketDict Workbench 0.1

Product-first local control plane over the real RocketDict core.

## What this milestone already does

- creates an isolated RocketDict project and real migrated SQLite database;
- refuses to run when the real RocketDict core is unavailable;
- imports `.srt`, `.vtt`, `.ass`, `.ssa`, `.txt` into immutable RocketDict storage and immediately runs source interpretation/format recognition;
- exposes the live Lab Registry rather than maintaining a second hard-coded list of tools;
- stores a default production candidate generated by the same registry/adapter ABI used by RocketDict execution;
- creates and runs real Stage-28 Lab/experimental campaigns;
- exports machine-readable experiment evidence (`JSON`, `JSONL`, `CSV`, `Markdown`);
- creates an additional self-contained, Russian-language human report with trial table, Pareto rank, per-objective charts, pairwise plots, comparisons and parameter-effect sections;
- generates dictionary-shaped lexical OPUS evidence and can run real Stage20 over the frozen provider snapshot;
- can explicitly apply `lexical-primary-arbitration-v1` after Stage20, requiring the selected dictionary headword to already exist as an accepted model-evidenced candidate and persisting the arbitration request/result as durable JSON evidence;
- has a resumable downstream Product runner connecting Stage20 arbitration → pinned CEFR-J → exact CMUdict pronunciation → sense-scoped Stage23 examples;
- has an executable fail-closed Product preflight that freezes the immutable source, durable import/document identities, real core/API identity, live registry, selected Stage8–19 adapters/settings and exact hard-quality-gate identity before upstream execution is allowed;
- has a unified `rocketdict-workbench-product-run/1` root state anchored to that immutable preflight fingerprint;
- probes the exact runtime into structured callable evidence (`rocketdict-core-api-surface-probe/2`) rather than treating operation-name strings as executable proof;
- can promote a Stage8 callable to `rocketdict-workbench-upstream-binding/1` only when its exact runtime metadata matches the frozen Product Stage8 contract;
- never substitutes fake/identity MT for a missing backend.

## Two modes, one core

`Create dictionary` is the product path: the workbench should choose a validated production profile and execute the real end-to-end RocketDict pipeline.

`Research` exposes the same registry/adapters as a matrix of implementations and settings. Research trials do not use a parallel algorithm stack: they execute the same core through immutable ExperimentBench definitions/plans and retain failed/pruned alternatives as evidence.

## Runtime model

Workbench is intentionally a thin orchestration layer. The algorithms remain in `rocketdict`.
For recovery/development an unpacked core can be supplied with `--core-pythonpath`; a packaged build will point to the bundled RocketDict runtime.

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core doctor
rocketdict-workbench --core-pythonpath /path/to/unpacked-core create ./my-project --name "Movie subtitles"
rocketdict-workbench --core-pythonpath /path/to/unpacked-core import ./my-project ./movie.srt
rocketdict-workbench --core-pythonpath /path/to/unpacked-core catalog ./my-project --output ./catalog.json
rocketdict-workbench --core-pythonpath /path/to/unpacked-core default-config ./my-project
rocketdict-workbench --core-pythonpath /path/to/unpacked-core product-preflight ./my-project
rocketdict-workbench --core-pythonpath /path/to/unpacked-core product-run-init ./my-project
rocketdict-workbench --core-pythonpath /path/to/unpacked-core serve ./my-project
```

Research campaigns use the existing RocketDict Lab/ExperimentBench contracts, not a parallel experiment engine.

### Mandatory Product preflight

Before a future full Product run is allowed to execute Stage8–19, Workbench can create a durable `rocketdict-workbench-product-preflight/1` evidence record:

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core product-preflight ./my-project
```

The preflight is intentionally stricter than merely loading `product-*.json`. It:

1. selects an already imported immutable source and recomputes the copied file SHA-256 and byte size;
2. rejects project-relative source paths that escape the Workbench root;
3. freezes the import/interpretation payload hashes **and** requires durable `import_event_id`, `document_version_id` and selected source format;
4. requires the real RocketDict core to be available and records its version/API identity;
5. probes the live Lab Registry at runtime rather than trusting a stale catalog;
6. rebuilds the Product Profile from that live registry and requires matching registry identity;
7. requires the selected real Stage8, 10, 12, 14, 16, 17 and 19 implementations to be locally available;
8. validates Product policy, including the prohibition on fake/identity MT and the accepted OPUS float32 rule;
9. requires the exact Stage15 hard-gate set (`numeric-symbol`, punctuation and length-ratio preservation);
10. freezes selected implementation keys, adapter descriptor hashes and parameter hashes into one immutable preflight fingerprint.

If a project has more than one imported source, Product Mode refuses to guess which one is authoritative:

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core product-preflight ./my-project \
  --source-sha256 <exact-imported-source-sha256>
```

`--source-kind subtitle|text` is an optional assertion and must agree with the imported source suffix. `--output` can choose the evidence path; otherwise the record is written below `experiments/product-preflight/` using the fingerprint prefix.

### Unified Product run root and structured real-core API probe

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core product-run-init ./my-project
```

`product-run-init` rebuilds the strict Product preflight and creates/resumes an atomic `rocketdict-workbench-product-run/1` state. Its immutable root contains the preflight fingerprint, source SHA, `import_event_id`, `document_version_id`, selected source format, registry hash and real core/API identity.

The state machine is explicit:

1. `preflight` — completed and stored as immutable root evidence;
2. `upstream_contract_probe` — probes the exact `rocketdict.api` package in the same real runtime;
3. `upstream_execution` — remains pending until an exact Stage8 operation binding is proven;
4. `stage20_downstream` — future bridge to the already-working downstream runner;
5. `cards` — pending;
6. `export` — pending.

Probe schema v2 records both discovery-level and proof-level observations:

- RocketDict version and API version;
- modules exposed under `rocketdict.api` and module source SHA-256 when introspection is available;
- discoverable argparse parser command paths;
- public callable-mapping keys;
- for each callable mapping entry: mapping module/name, exact operation key, callable module/qualname, signature, structured parameter names/kinds/required flags, inspectable callable source SHA-256, and explicit binding metadata published by that runtime;
- one immutable probe fingerprint over all observations.

Parser paths and mapping keys remain **candidates only**. They are never promoted merely because their names look like Stage8 or Product operations.

### Exact-runtime Stage8 binding promotion

After `product-run-init`, a Stage8 operation may be promoted only from structured callable evidence:

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core product-run-bind-stage8 ./my-project \
  --state ./my-project/experiments/product-run/<fingerprint>.json \
  --operation <exact-operation-key>
```

The verifier fails closed unless the callable itself explicitly publishes metadata matching all frozen Product identities: Stage 8, the exact Stage8 `stage_key`, implementation key, adapter descriptor SHA-256, and required inputs exactly `document_version_id`. It also requires inspectable callable source SHA-256 and matching preflight/probe RocketDict/API identities.

The persisted binding freezes the selected `document_version_id`, preflight fingerprint, Product-run root fingerprint, registry hash, core/API versions, probe fingerprint, operation identity, callable signature/source hash, Product implementation/descriptor and parameter hash. Re-verifying unchanged evidence is idempotent; mutation of persisted binding evidence is rejected.

**Important:** the Workbench CI verifies this promotion contract with controlled evidence. It does not prove that the incomplete public newer-core payload currently contains a real Stage8 callable carrying this metadata. Until an exact runtime probe observes such a callable, Product Stage8 remains unexecuted. See `docs/PRODUCT_STAGE8_BINDING.md`.

### Product Stage20 lexical-primary arbitration

The lexical provider remains real OPUS model evidence; alignment remains context/occurrence evidence rather than dictionary-headword authority. To execute Stage20 and then promote only the frozen provider primary that is already present in the generation run with accepted model provenance:

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core lexical-opus ./my-project \
  --model-path /path/to/opus-en-ru-ct2 \
  --revision opus-2020-02-11 \
  --archive-sha256 <verified-opus-archive-sha256> \
  --source-uri <official-source-uri> \
  --apply-stage20 \
  --arbitrate-primaries
```

`--arbitrate-primaries` fails closed unless `--apply-stage20` is present. `--arbitration-output` may be used to choose the durable audit JSON path; otherwise Workbench writes a sibling `*.stage20-arbitration.json` file next to lexical provider evidence.

### Resumable downstream Product runner

The same lexical command can continue the strict product path instead of stopping at Stage20:

```bash
rocketdict-workbench --core-pythonpath /path/to/unpacked-core lexical-opus ./my-project \
  --model-path /path/to/opus-en-ru-ct2 \
  --revision opus-2020-02-11 \
  --archive-sha256 <verified-opus-archive-sha256> \
  --source-uri <official-source-uri> \
  --apply-stage20 \
  --continue-product \
  --cefrj-asset ./my-project/data/assets/cefrj-vocabulary-profile-1.5.csv
```

This route persists an atomic `rocketdict-workbench-product-downstream/1` state file. A repeated run with the same immutable provider hash, Stage20 revision identities, pinned CEFR-J hash and output-affecting settings reuses completed steps. Changing any of those inputs fails closed instead of mixing evidence from different runs.

Current downstream order:

1. Stage20 `lexical-primary-arbitration-v1`;
2. pinned CEFR-J 1.5 assessment;
3. exact CMUdict pronunciation with generated fallback forbidden;
4. Stage23 sense-scoped examples.

The Stage23 validator additionally requires its approved sense-translation revision to be exactly the revision produced/validated by the arbitration step. A newer or unrelated approved revision is treated as identity drift and stops the run.

`--product-state` can select the state JSON location. Without it, Workbench writes a sibling `*.product-downstream.json` next to lexical provider evidence. `--include-russian-pronunciation-hint` is part of the immutable run fingerprint, so changing it cannot silently reuse a pronunciation result produced under different settings.

## Fail-closed subtitle handling

A subtitle file is not allowed to silently degrade into plain TXT. If the selected core/runtime cannot actually parse the declared subtitle format, Workbench stops and reports the missing runtime capability. The currently recovered 0.30.34 core needs `pysubs2` for SRT/VTT/ASS/SSA recognition.

## Current boundary

Workbench 0.1 now has a real core bridge, project/database lifecycle, import/interpretation, dynamic Lab Registry, strict immutable Product preflight, unified Product run root, structured real-core API probe, fail-closed Stage8 binding verifier, real ExperimentBench campaigns, machine exports, human reports and a local browser control surface. The downstream lexical path remains executable and resumable through Stage23.

The product button for the complete dictionary pipeline remains disabled. The verifier is ready to promote a real Stage8 binding, but the current public handoff still lacks enough exact newer-core payload to claim that such a callable has actually been observed. Stage8 invocation itself and final cards/export are therefore still unwired.

## Next product milestone

Run the probe against the exact recoverable/newer RocketDict core. If it exposes a unique callable whose explicit metadata passes `product-run-bind-stage8`, persist that real binding and implement the first resumable Stage8 invocation with durable input/result hashes and output revision IDs. After Stage8 is genuinely executable, advance the same state through real MT → hard integrity gates → approved translation → alignment → lexical/sense induction, then reuse Stage20→Stage23 and finally add cards/export.
